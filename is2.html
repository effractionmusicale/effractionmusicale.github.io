Faust in 5 minutes

What is Faust?

  • A functional language dedicated to real-time audio signal processing
  • Designed at GRAME (Lyon) in the early 2000s; free software (GPL / LGPL)
  • A Faust program describes a circuit: a function from signals to signals
  • The compiler generates optimized code: C++, C, Rust, WebAssembly, LLVM, VHDL, Cmajor…
  • … and complete applications thanks to architectures: plugins, PWAs, Android, iOS, Bela, Daisy, ESP32, Teensy, OWL, FPGA…

A first program

import("stdfaust.lib");
process = hslider("freq", 440, 50, 2000, 1) : os.osc : *(0.2);

Where does Faust come from?

Rewriting systems (Axel Thue, 1914)

Describing transformations with simple replacement rules. A row of coffee beans, and three rules:

○○●●○○●●○○●●○○●●

●○●○ →\rightarrow ●● (r1)
○●○● →\rightarrow ●● (r2)
●●●● →\rightarrow ○○ (r3)
○○●●○_○●●○○●\underline{●○}○●● (r1)
○○●●_○●●○○\underline{●●}○●● (r3)
○○○○●_●○○○\underline{○●}● (r2)
○○○●_●○○\underline{○●}● (r2)
○○●_●○\underline{○●}● (r2)
○●_●\underline{○●}● (r2)
●●_\underline{●●} (r3)
○○ normal form
○○●●_○○●●○○\underline{●●}○○●● (r3)
○○○○○●●_○○○○○\underline{●●} (r3)
○○○○○○○○○○○○ normal form

Two orders of application, two normal forms: this system is not confluent. A confluent system defines a computation.

Rewriting rules (pattern matching), evaluated at compile time, transform circuits. Examples later on.

Combinatory logic (Moses Schönfinkel, 1924)

  • M. Schönfinkel, Über die Bausteine der mathematischen Logik, 1924; then H. B. Curry
  • Idea: do away with variables altogether
  • Three combinators suffice:

Sxyz→xz(yz)Kxy→xIx→xS\,x\,y\,z \to x\,z\,(y\,z) \qquad K\,x\,y \to x \qquad I\,x \to x

_ (identity), ! (cut) and the composition operators are enough to assemble circuits without naming signals.

Lambda calculus (Alonzo Church, 1936)

  • A. Church, An Unsolvable Problem of Elementary Number Theory, 1936; then The Calculi of Lambda-Conversion, 1941
  • A language reduced to its essence: abstraction and application
  • Functions are values like any other
square = \(x).(x*x);      // abstraction
process = square(0.5);     // application

Circuits are values like any other: they can be passed as arguments, returned and assembled. Above, an abstraction and an application written in Faust.

A block diagram compiler (Kelly, Lochbaum, Vyssotsky, 1961)

Fig. 1 of A Block Diagram Compiler, Bell System Technical Journal 40(3), May 1961

  • BLODI, Bell Labs: same issue as Mathews’s paper
  • “Corresponds closely to an engineer’s block diagram”: ~30 box types, wired on punched cards
  • Sampled signals; loops without delay rejected

The same circuit (without the printer): the delay box τ\tau is the ~ operator itself, so a loop without delay cannot be written.

h       = (.001,.002,.004,.008,.016,.032,
           .063,1/8,.230,1/4,1/5,.057);
loop    = (ro.cross(2) : - : +(no.noise) : fi.fir(h)) ~ _;
process = loop : mem : *(2) : max(0);

Unit generators (Max Mathews, Music III, 1960)

Photo: vonguard (cropped), CC BY-SA 2.0

  • Bell Labs, with Joan Miller: An Acoustic Compiler for Music and Psychological Stimuli, 1961
  • Unit generators: oscillators, adders, envelopes… connected to build instruments
  • Model for Music V, Csound, SuperCollider…, four years before Moog’s modules
phasor(f) = f/ma.SR : (+ : ma.frac) ~ _;
osc(f)    = sin(2*ma.PI*phasor(f));
process   = osc(440) * 0.2;

In Music N, unit generators are primitives written in another language. In Faust, they are written in Faust: above, an oscillator built from a phasor, down to the sample.

The Unix pipe (Doug McIlroy, 1964)

Photo: Denise Panyik-Dale, CC BY 2.0

We should have some ways of coupling programs like garden hose — screw in another segment when it becomes necessary to massage data in another way.

M. D. McIlroy, Bell Labs internal memo, October 11, 1964

  • The idea becomes the Unix pipe |: the output of one program feeds the input of the next
  • Programs written independently of each other compose, thanks to a uniform interface

The five composition operators A:B, A,B, A<:B, A:>B and A~B are wiring operations; A:B is the pipe.

Modular synthesizer (Robert Moog, 1964)

Moog Music brochure, c. 1974, public domain

  • October 14, 1964, AES convention in New York: Voltage-Controlled Electronic Music Modules
  • Independent modules (oscillators, amplifiers, envelopes) connected by patch cords
  • Control voltage: one signal can drive a parameter of another module
  • Three days after McIlroy’s memo: composition by patching, in music as in computing

Widget modulation plays the role of control voltage: a signal modulates a parameter of an existing circuit, without changing its code.

FP, an algebra of programs (John Backus, 1977)

  • J. Backus, Can Programming Be Liberated from the von Neumann Style?, Turing Award 1977
  • Programming by composing functions, with algebraic laws
FP [+,*]:<2,3>
Faust 2,3 <: +,*

Like FP, Faust relies on a few combining forms, its five operators, which obey algebraic laws, e.g. (A:B):C = A:(B:C). This is Faust’s block-diagram algebra (Orlarey, Fober, Letz, ICMC 2002).

A program is a circuit

Three readings of the same program

  • Code, diagram and formula: the last two are produced by the compiler
  • Signal = function of time; circuit = function of signals; operator = function of circuits

Five operators to assemble circuits

Operator Name Example Circuit
A : B sequential os.osc(440) : *(0.2)
A , B parallel os.osc(440), os.osc(660)
A <: B split 1 <: sin, cos
A :> B merge -8, 3 :> abs
A ~ B recursive + ~ *(0.9)

Composing programs

Composing like the Unix pipe

ls | grep dsp | wc -l
  • Three independent programs, written without knowing each other
  • They compose thanks to a uniform interface: a text stream
  • f : g in Faust ≈\approx f | g in Unix ≈\approx g∘fg \circ f in mathematics

What about C++?

  • Two C++ programs = two main() functions
  • To combine them into a third one, you have to rewrite them:
    • turn them into libraries,
    • define a common interface (buffers, formats, clock),
    • write the glue code and the user interface
  • A C++ program is not a value of the language

Two independent programs

synth.dsp: a sawtooth with adjustable frequency

import("stdfaust.lib");
freq = hslider("freq", 220, 50, 1000, 1);
process = os.sawtooth(freq) * 0.2;

echo.dsp: an echo with feedback

import("stdfaust.lib");
d  = hslider("delay", 0.25, 0, 1, 0.01);
fb = hslider("feedback", 0.5, 0, 0.95, 0.01);
process = + ~ (de.delay(ma.SR, d*ma.SR) * fb);

A third program: component

combo.dsp

process = component("synth.dsp") : component("echo.dsp");

  • Each program becomes a circuit, assembled with the : operator
  • The user interfaces are merged automatically: freq, delay, feedback

All the operators apply

// in parallel: two independent synths, stereo output
process = hgroup("L", component("synth.dsp")),
          hgroup("R", component("synth.dsp"));

// one source, two processing paths
process = component("synth.dsp") <: component("echo.dsp"), _;

// sample-accurate feedback between programs
process = component("synth.dsp")
        : + ~ (component("echo.dsp") : *(0.3));
  • Two widgets with the same path are shared: without the hgroups, a single freq slider
  • Composition happens at compile time: the result is a single optimized program
  • A ~ loop costs one sample of delay; between plugins in an audio host, at least one block

Rewriting in Faust

  • Computing with rules: an expression that matches a pattern is replaced by another
  • In Faust, rules evaluated at compile time, matching the structure of circuits:
serial((x,xs)) = x : serial(xs);
serial(x)      = x;

process = serial((fi.lowpass(2,2000),
                  fi.highpass(2,200), *(0.5)));

  • A Turing-complete meta-language: it builds circuits, then vanishes

Rewriting: Julius Smith’s FFT

fftb(1) = _,_;                 // a complex number (re, im)
fftb(N) = si.cbus(N)
        : (fftb(No2) <: (si.cbus(No2), si.cbus(No2))),
          (fftb(No2) <: (si.cbus(N) : twiddleOdd(N)))
       :> si.cbus(N)
with { No2 = int(N)>>1; ... };

  • Cooley-Tukey radix-2 FFT in two rules (analyzers.lib); the compiler unfolds the recursion: here fftb(4)

Customizing without modifying

Explicit substitution

process = component("synth.dsp")[freq = 110 + 50*os.osc(0.5);]
        : component("echo.dsp");
  • [ ... ] redefines an internal definition of the program, without touching its file
  • Here, the freq slider is replaced by an LFO: it disappears from the interface
  • Possible because each expression keeps its lexical environment (closure)

Substitution and replication

process = par(i, 4, component("synth.dsp")[freq = 110*(i+1);]) :> _;

  • Four copies of the same program, each tuned to a harmonic
  • Additive synthesis in one line
  • The compiler resolves everything: only the four oscillators remain

Widget modulation

The problem

  • I want to modulate the frequency of synth.dsp with an LFO
  • The freq slider is inside the program: no input gives access to it
  • Substitution replaces it, but I lose manual control
  • Without a dedicated mechanism, the program’s code must be modified

Modulating a widget from the outside

["freq" -> component("synth.dsp")]
  • Adds an input to the circuit, which modulates the freq slider
  • By default, the modulation signal multiplies the slider value
  • The code of synth.dsp is left unchanged
Form Effect
["freq" -> C] new input, combined with *
["freq":+ -> C] new input, combined with +
["freq":*(lfo) -> C] internal modulation, no new input
["freq":440 -> C] the slider is replaced by a constant

lfo = 1 + 0.5*os.osc(

             -> synth.out]

Demo: an AI, a DSL and a foghorn

The challenge

  • Reproduce the sound of a foghorn in Faust from a recording (22 s)
  • Let’s listen to the target
  • The difficulty: a language model cannot hear
    • it can reason about a sound, write DSP code, measure a spectrum…
    • … but the judgment “does it sound right?” is beyond its reach
  • The question: which feedback best makes up for this deafness?

The setup

Actor Role
Claude Code reads and writes files, analyzes the target and its own renderings in Python
faustcode (browser + MCP bridge) compiles and plays each version; render_audio: offline rendering, per-phase metrics, WAV
Faust the notation: a complete model in ≈\approx 100 lines, checked by the compiler
Me the ear, when the AI asks for it

The prompt

Model this foghorn in Faust. Do not fall into the trap of static additive synthesis — faithfully reproduce the full spectral evolution, especially the attack. Work by measurement: first extract the target’s characteristics (envelope by phase, f0f_0 with sub-harmonic correction, harmonic profile, HNR, roughness), then iterate by comparing your rendering to the target on these same metrics at every step. Decide on the synthesis approach based on what the measurements say, and let me know when you need my ear.

Conclusion

Why Faust makes this possible

  • Functional semantics: a program is a circuit, and circuits form an algebra (5 operators)
  • Lexical environments: component, library, environment and the [...] substitution handle programs as values
  • Compile-time composition: no runtime cost, sample-accurate feedback
  • User interfaces derived from the code: they compose with it, and widget modulation makes them modulable

Notation as a tool of thought

  • A notation is not merely a means of communicating or remembering: it is a cognitive tool
  • Algebra made it possible to manipulate objects unthinkable in natural language (differential equations, transforms)
  • Musical notation made large forms possible, such as the symphony
  • Faust is a notation for signal processing algorithms, directly connected to their efficient implementation

Why a DSL with strong semantics also helps AI

Faust C++
Meaning / syntax ratio the code describes the algorithm buffers, loops, data structures
Composition A : B explicit buffer and block management
State no explicit mutable state mutable state everywhere
Size a few dozen lines several files, hundreds of lines
  • The whole program fits in the context window
  • The compiler checks the code and provides views (diagrams, signals, errors): structured feedback

In a nutshell

Like us, AIs need notations and feedback loops to create.

  • A compact notation with strong semantics: Faust
  • A protocol to act and observe: MCP
  • Measurements to stand in for the ear… and the human ear to decide
